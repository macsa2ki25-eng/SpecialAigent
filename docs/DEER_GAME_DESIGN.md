# 『下ばっか見てると』/ Mind the Deer — 企画構成案 v0.3

スマホ向けHTML5ゲーム。**16bit風ドット絵の縦スクロール避けゲー**。全100ステージ＋エンドレス。
最終的に iOS App Store へ。**実装前の構成案**。

改訂履歴:
- v0.1 擬似3D＋視点切り替え → 方向性が違ったため破棄
- v0.2 ドット絵の縦スクロールへ全面改稿
- v0.3 指のオフセット / 参道外への脱出バグ / 横画面モードを追加

---

## 1. v0.3 で直したところ

### 1.1 指で自分が見えない

キャラを**指先の少し先（初期値10mm）に置く**方式に変更。
指の位置とキャラの位置を切り離し、追従は指数補間（約25/秒）で滑らかに。

最適な距離は人と端末で変わるので**設定項目として残す**（0〜20mm）。
mm指定にしているのは、端末の画面サイズが変わっても**指と絵の物理的な距離を一定に保つ**ため。
論理ピクセル固定だと、大きい端末で近すぎ・小さい端末で遠すぎになる。

```
offsetLogicalPx = mm × (96 / 25.4) × (論理幅 / CSS表示幅)
```

### 1.2 両サイドの緑地に逃げれば無敵だった

明確なバグ。**参道の外へは出られないようにした**。
見えない壁だと理不尽なので、参道の縁に**植え込みを描いて壁だと分かるように**している。
フンの生成範囲も参道の端から端までに拡大。

> 避けゲーに安全地帯があると、その瞬間にゲームが壊れる。
> 「理不尽にしない仕組み」（6章）に恒久ルールとして追記した。

### 1.3 横画面モード

追加。前方の視界が短くなるぶん、フンも鹿も**「急に現れる」**感じが強く出る。
ただし代償があるので次章。

## 2. 縦と横、どちらを取るか

横画面は「急に現れる」感じが強い。ただし**前方の視界が16.6タイルから9.4タイルへ、約4割減る**。
反応時間の下限（1.2秒）を守るには、そのぶん**速度の上限を下げるしかない**。

| | 縦画面 | 横画面 | 意味 |
|---|---:|---:|---|
| 論理解像度 | 160×288 | 288×160 | どちらも16pxタイル |
| 参道の幅 | 128px / 8タイル | 240px / 15タイル | 横は**倍近く広い** |
| 前方の視界 | 16.6タイル | 9.4タイル | 横は**4割短い**＝急に現れる |
| スクロール速度の上限 | 9.14 t/s | 5.16 t/s | 横は**速くできない** |
| 鹿の速度の上限 | 4.71 t/s | 2.66 t/s | 同上 |
| フン密度の上限 | 2.20 /行 | 4.12 /行 | 横は**濃くできる** |
| 回廊のずれ幅/行 | 7.9〜24px | 19〜50px | 横は蛇行を大きく作れる |

### 結論：横画面を推す

横は「速さ」で難しくできないが、かわりに**「濃さ」と「横移動の量」で難しくできる**。
参道が15タイル幅あるので、フンの配置で作れる形が段違いに増える
——**100ステージ作るなら、こちらのほうが持つ**。
縦画面は速度で殴る作りになりがちで、後半のステージが似通う。

そして最初の着想「前から鹿がぬっと来る」感覚は横画面のほうが出る。
横画面では**左右の辺からも鹿が入る**ようにして、短い前方視界のぶんのテンポを取り戻す。

**両方を製品に入れるのは勧めない。** ステージの型が向きごとに別物になり、
100ステージぶんの設計が二重になる。どちらかに決めること。

## 3. 画面とドット絵の仕様

| 項目 | 縦画面 | 横画面 |
|---|---:|---:|
| 論理解像度 | 160 × 288 | 288 × 160 |
| 参道 | x 16〜144 (128px) | x 24〜264 (240px) |
| プレイヤー可動域 y | 32〜248 | 24〜132 |
| 横移動速度 LAT | 72 px/s | 100 px/s |

共通:

| 項目 | 値 | 理由 |
|---|---:|---|
| タイル | 16 × 16 px | SFC標準 |
| パレット | 32色 | 1スプライト15色以内。SFCの制約に合わせると絵が締まる |
| プレイヤー | 12 × 16 | 後ろ姿。歩き2フレーム |
| 鹿 | 16 × 18 | 正面向き |
| フン | 8 × 5 | 茶色の小山。デフォルメ徹底（4+レーティング） |
| フレームレート | 60 fps | 固定タイムステップ更新、rAF描画 |

**当たり判定はスプライトより小さく取る**。プレイヤーは**足元 8×6px だけ**。

## 4. 操作

- キャラの中心 ＝ **指の接触点から進行方向へ 10mm**（設定で0〜20mm）
- 追従は指数補間（約25/秒）。瞬間移動もしないし、置いていかれもしない
- タップした瞬間にワープしない：現在位置から目標へ滑らかに寄る
- 指を離しても位置は保持。押し直しでその場から再開
- 矢印キーでも操作可
- 滑り状態では追従係数も0.35倍（見た目と操作感を一致させる）

## 5. 出てくるもの

| 要素 | 動き | 当たると |
|---|---|---|
| 鹿のフン | 静止（背景と一緒に流れる） | 汚れ+1、コンボ消滅、少し滑る |
| 鹿（メス・子） | 正面から降りてくる | 汚れ+3、転倒0.35秒、押し戻される |
| 横入り鹿 *(横画面のみ)* | 左右の辺から歩いて横切る | 同上。短い前方視界を補うテンポ役 |
| 追い鹿 | 横位置をゆっくり合わせてくる | 同上。距離1000mから増える |
| 牡鹿（角あり） | 0.8秒ためて高速直進 | 同上。距離800mから |
| 寝鹿 | 背景に見えるが近づくと立ち上がる | 同上。「不意打ち」担当 |
| 観光客 | ゆっくり同方向へ歩く | 汚れなし。押し戻される |
| 水たまり | 静止 | 1秒間、横移動が効きにくい |
| 石灯籠・柱 | 静止・通り抜け不可 | 鹿がその陰から出てくる |
| 鹿せんべい *(item)* | 拾える | 倍率×1.5〜2.5。鹿の出現間隔が0.7倍 |
| おまもり *(item)* | 拾える | 汚れを1つ消す |

**観光客は障害物ではなくヒント。** 観光客は*フンを踏まない*ので、
歩いた跡をなぞれば足元は安全。観光客モードはこれが主役。

## 6. エンドレスの難易度カーブ

すべて**飽和する関数**にする。上限が無いと必ず理不尽になる。
上限そのものは**画面の向きから逆算**する。

```
D = 進んだ距離 [m]   ※ 1m = 1タイル = 16px

── まず向きから上限を決める ───────────────
前方視界 FIELD = (プレイヤー安全帯のy − 鹿の出現y) / 16   [タイル]
反応時間の下限 T_min = 1.2 [s]                （設計値・動かさない）
接近速度の上限 = FIELD / T_min
  v_max = 0.66 × 接近速度上限      u_max = 0.34 × 接近速度上限

  縦画面: FIELD 16.6 → v_max 9.14, u_max 4.71
  横画面: FIELD  9.4 → v_max 5.16, u_max 2.66

── そのうえでカーブを引く ─────────────────
スクロール速度  v(D) = v0 + (v_max − v0)·(1 − e^(−D/1800))
鹿の接近速度    u(D) = min(u_max, u0 + 0.55·ln(1 + D/300))
フン密度        ρ(D) = (0.5 + 1.7·(1 − e^(−D/1400))) × (参道幅 / 128)
鹿の出現間隔    I(D) = max(0.55, 4.0·e^(−D/2200))
追い鹿の割合    h(D) = min(0.45, D/6000)
牡鹿の割合      c(D) = min(0.20, (D−800)/8000)        ※ D > 800 から

  v0/u0 = 縦画面 3.0/1.0、横画面 2.0/0.8
```

横画面での実計算値（推奨案）:

| 距離 | 速度 | 鹿速度 | フン/行 | 鹿間隔 | 反応時間 | 回廊drift |
|---:|---:|---:|---:|---:|---:|---:|
| 0 m | 2.00 | 0.80 | 0.94 | 4.00s | 3.35s | 50px |
| 500 m | 2.77 | 1.34 | 1.89 | 3.19s | 2.28s | 36px |
| 1000 m | 3.35 | 1.61 | 2.56 | 2.54s | 1.89s | 30px |
| 2000 m | 4.12 | 1.92 | 3.36 | 1.61s | 1.55s | 24px |
| 3000 m | 4.56 | 2.12 | 3.75 | 1.02s | 1.40s | 22px |
| 5000 m | 4.96 | 2.38 | 4.04 | 0.55s | 1.28s | 20px |
| ∞ | 5.16 | 2.66 | 4.12 | 0.55s | 1.20s | 19px |

### 500mごとに3秒の休憩を入れる

フンも鹿も出ない区間を挟み、地名（一町、二町…）を出す。
エンドレスは緩急が無いと必ず飽きる。ここは削らないこと。

## 7. 理不尽にしない仕組み

### 安全回廊（corridor）方式

配置後に検査するのではなく、**先に通れる道を引いてから、その外側に置く**。

- 幅24px（プレイヤー12px＋余裕12px）の回廊を、参道の中で蛇行させる
- 回廊が1行（16px）で横にずれてよい量は **LAT ÷ v(D) px**
  ——プレイヤーが確実に追いつける範囲。横画面なら最悪でも19px/行
- フンは回廊の外だけに置く。回廊内には置かない
- 鹿は回廊を**塞いでよい**。ただし1頭まで、かつ回廊幅の半分まで

フンは最大密度でも参道の**14%**しか埋めないので、回廊を確保しても密度は十分出る。

### そのほかの保証

- **予兆**: 鹿が画面に入る0.5秒前、入ってくる辺に印と音。牡鹿はさらに0.8秒のため
- **反応時間の下限**: **1.2秒**。これを固定して、そこから速度上限を逆算する
- **無敵時間**: 被弾後0.5秒（フン）／1.2秒（鹿）。連鎖事故を防ぐ
- **判定は小さめ**: プレイヤーは足元8×6pxのみ
- **逃げ場を作らない**: 参道の外へは出られない。安全地帯があると避けゲーは即座に壊れる

## 8. スコアと失敗

### ためる
- 距離 ×10
- **前進倍率** 画面の手前 ×1.0 → 奥 ×2.0（奥にいるほど反応時間が減る）
- **連続倍率** フンを踏まず10m進むごとに ×1.1（上限 ×3.0）
- 鹿せんべい ×1.5〜×2.5

### くずれる
- 汚れゲージのみが体力。**10で終了**。フン+1、鹿+3
- 鹿に当たると手前へ押し戻される＝倍率も落ちる。二重の罰だが即死ではない
- 結果画面は**汚れた靴の裏を大写し**にして S / A / B / C

## 9. ステージ100の作り方

10エリア × 10ステージ。レベルは**チャンク（8〜16行の型）の組み合わせ**で生成。
型を70個ほど手で作れば、100ステージぶんの地形はそこから出る。

| ステージ | エリア | 内容 |
|---|---|---|
| 1–10 | 参道 | チュートリアル。フンのみ → 鹿1頭 |
| 11–20 | 大門 | 柱で通路が狭まる。柱の陰から鹿 |
| 21–30 | 鏡の池 | 水たまり。滑って止まれない |
| 31–40 | 大仏さまの前 | 観光客の群れ。人の流れを読む |
| 41–50 | 若草の坂 | スクロールが速い。上り下りで速度が変わる |
| 51–60 | 石段 | 横移動が段単位に制限される |
| 61–70 | 春日の杜 | 木漏れ日以外が暗い。フンが見えにくい |
| 71–80 | 鹿寄せ広場 | 鹿が大量。せんべいで誘導して道を作る |
| 81–90 | 雨の参道 | 水たまり多数。フンと見分けがつかない |
| 91–100 | 夜の奈良 | 暗闇。鹿の目だけが光って見える |

- 距離は 40m（エリア1）→ 140m（エリア10）。**1ステージ40〜90秒**
- 各エリアの**10番目はボス**
- 評価は**★3段階**: 汚れ0で★★★、1〜2で★★、3〜9で★
- 次エリアの解放は**★15個以上**
- 難易度はエンドレスと**同じ式**を使い、ステージ番号を距離に読み替える

## 10. 技術構成

### 実装
- **TypeScript + Canvas 2D + Vite**。canvasをCSSで整数倍に拡大、`image-rendering: pixelated`
- 更新は固定タイムステップ1/60秒。描画はrAF
- スプライトは1枚のPNGに詰めてbase64で内蔵。**完全オフライン**
- BGMはWebAudioで矩形波・ノイズを実行時合成（音源ファイル不要）。効果音は短いサンプル
- 保存はlocalStorage（★の取得状況、ハイスコア、指のオフセット設定）

### iOSに載せる
- **Capacitor**でラップ。アセット全部ローカル同梱、サーバー参照なし
- オフライン完結＋ハプティクス＋Game Centerを入れておけば「単なるWebサイトの外皮」判定は通常立たない
- **横画面固定**（推奨案の場合）・iPhone先行。レーティング4+
- 実在名は避けて架空の古都に。奈良らしさは残す

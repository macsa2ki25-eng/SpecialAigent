# 『下ばっか見てると』/ Mind the Deer — 企画構成案 v0.2

スマホ向けHTML5ゲーム。**16bit風ドット絵の縦スクロール避けゲー**。全100ステージ＋エンドレス。
最終的に iOS App Store へ。**実装前の構成案**。

> v0.1 では擬似3D＋視点切り替えを提案したが、方向性が違ったため破棄。
> 本書がその置き換え。

---

## 1. 方針

スーパーファミコン期の見下ろし型ドット絵。背景が下へ流れる普通の縦スクロール。
プレイヤーは画面内を8方向に動き、静止したフンと、上から降りてくる鹿をよける。

**擬似3D・視点切り替えは使わない。**

### 元のジレンマは別の形で残す

「下を見るか前を見るか」は消えるが、次の形に置き換えられる。

> **画面の上に出るほど強くなる代わりに、反応時間が減る。**

プレイヤーの**画面上の高さがそのままスコア倍率**（下端 ×1.0 → 上端 ×2.0）。
上に行くほど稼げるが、鹿が画面に入ってから接触するまでの猶予が短くなる。
「前のめりに歩くと危ない」という感覚は、これで2Dのまま成立する。

## 2. 画面とドット絵の仕様

整数倍スケーリング前提。3倍で 480×864、4倍で 640×1152。

| 項目 | 値 | 理由 |
|---|---:|---|
| 論理解像度 | 160 × 288 | 10×18タイル。9:16にほぼ一致し整数倍で割り切れる |
| タイル | 16 × 16 px | SFC標準。参道は8タイル(128px)、両脇に草1タイルずつ |
| パレット | 32色 | 1スプライト15色以内。SFCの制約に合わせると絵が締まる |
| プレイヤー | 12 × 16 | 後ろ姿。歩き2フレーム |
| 鹿 | 16 × 18 | 正面向き。こちらへ降りてくる |
| フン | 8 × 5 | 茶色の小山。デフォルメ徹底（4+レーティング） |
| フレームレート | 60 fps | 更新は固定タイムステップ、描画はrAF |

**当たり判定はスプライトより小さく取る**。プレイヤーは**足元 8×6px だけ**。
見た目で当たったのに判定が出ない、の逆をやると避けゲーは一気に気持ちよくなる。

座標系:

```
PX0 = 16, PX1 = 144        参道の左右端 (128px幅)
Y_TOP = 32, Y_BOT = 248    プレイヤーが動ける縦の範囲
LAT = 72 px/s              プレイヤーの横移動速度 (4.5 タイル/s)
```

## 3. 出てくるもの

| 要素 | 動き | 当たると |
|---|---|---|
| 鹿のフン | 静止（背景と一緒に流れる） | 汚れ+1、コンボ消滅、少し滑る |
| 鹿（メス・子） | まっすぐ降りてくる | 汚れ+3、転倒0.35秒、下へ押される |
| 追い鹿 | 横位置をゆっくり合わせてくる | 同上。距離1000mから増える |
| 牡鹿（角あり） | 0.8秒ためて高速直進 | 同上。距離800mから。ための間に横へ逃げる |
| 寝鹿 | 背景に見えるが近づくと立ち上がる | 同上。「不意打ち」を2Dで作る担当 |
| 観光客 | ゆっくり同方向へ歩く（＝下へ流れる） | 汚れなし。ぶつかると押し戻される |
| 水たまり | 静止 | 1秒間、横移動が効きにくい |
| 石灯籠・柱 | 静止・通り抜け不可 | 鹿がその陰から出てくる |
| 鹿せんべい *(item)* | 拾える | 倍率×1.5〜2.5。かわりに鹿の出現間隔が0.7倍 |
| おまもり *(item)* | 拾える | 汚れを1つ消す |

**観光客は障害物ではなくヒント。** 観光客は*フンを踏まない*ので、
観光客が歩いた跡をなぞれば足元は安全。邪魔なだけの存在に、読めば得をする裏の意味を持たせる。
観光客モードはこれが主役。

## 4. ステージ100の作り方

100個を手で作るのは現実的でないので、**10エリア × 10ステージ**に分け、
レベルは**チャンク（8〜16行の型）の組み合わせ**で生成する。
型を70個ほど手で作れば、100ステージぶんの地形はそこから出る。

| ステージ | エリア | 内容 |
|---|---|---|
| 1–10 | 参道 | チュートリアル。フンのみ → 鹿1頭 |
| 11–20 | 大門 | 柱で通路が狭まる。柱の陰から鹿 |
| 21–30 | 鏡の池 | 水たまり。滑って止まれない |
| 31–40 | 大仏さまの前 | 観光客の群れ。人の流れを読む |
| 41–50 | 若草の坂 | スクロールが速い。上り下りで速度が変わる |
| 51–60 | 石段 | 横移動が段単位に制限される |
| 61–70 | 春日の杜 | 木漏れ日以外が暗い。フンが見えにくい |
| 71–80 | 鹿寄せ広場 | 鹿が大量。せんべいで誘導して道を作る |
| 81–90 | 雨の参道 | 水たまり多数。フンと見分けがつかない |
| 91–100 | 夜の奈良 | 暗闇。鹿の目だけが光って見える |

### 1ステージの構造

- 距離は 40m（エリア1）→ 140m（エリア10）。**1ステージ40〜90秒**
- 各エリアの**10番目はボス**: 牡鹿の突進を3回さばく／鹿の群れを抜ける等
- 評価は**★3段階**: 汚れ0で★★★、1〜2で★★、3〜9で★
- 次エリアの解放は**★15個以上**。全部★3を取る必要はない
- 難易度パラメータはエンドレスと**同じ式**を使い、ステージ番号を距離に読み替える（式が1本で済む）

## 5. エンドレスの難易度カーブ

段階を切らずに連続で上げる。すべて**飽和する関数**にして無限に難しくならないようにするのが肝心
（上限が無いと必ず理不尽になる）。

```
D = 進んだ距離 [m]   ※ 1m = 1タイル = 16px

スクロール速度   v(D) = 3.0 + 6.0·(1 − e^(−D/1800))          [タイル/s]  3.0 → 9.0
フン密度         ρ(D) = 0.5 + 1.7·(1 − e^(−D/1400))          [個/行]    0.5 → 2.2
鹿の出現間隔     I(D) = max(0.55, 4.0·e^(−D/2200))           [s]        4.0 → 0.55
鹿の接近速度     u(D) = min(4.5, 1.0 + 0.55·ln(1 + D/300))   [タイル/s] 1.0 → 4.5
追い鹿の割合     h(D) = min(0.45, D/6000)
牡鹿の割合       c(D) = min(0.20, (D−800)/8000)              ※ D > 800 から
```

実計算値。「反応時間」＝鹿が画面に入ってから接触するまで。

| 距離 | 速度 | フン | 鹿間隔 | 鹿速度 | 追い鹿 | 安全帯 | 上端＋予兆 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 m | 3.00 | 0.50 | 4.00s | 1.00 | 0% | 3.90s | 1.13s |
| 500 m | 4.46 | 1.01 | 3.19s | 1.54 | 8% | 2.60s | 0.92s |
| 1000 m | 5.56 | 1.37 | 2.54s | 1.81 | 17% | 2.12s | 0.84s |
| 2000 m | 7.02 | 1.79 | 1.61s | 2.12 | 33% | 1.71s | 0.77s |
| 3000 m | 7.87 | 2.00 | 1.02s | 2.32 | 45% | 1.53s | 0.75s |
| 5000 m | 8.63 | 2.15 | 0.55s | 2.58 | 45% | 1.39s | 0.72s |
| 8000 m | 8.93 | 2.19 | 0.55s | 2.83 | 45% | 1.33s | 0.71s |

### 上端の倍率2.0は後半ほど使えなくなる — 仕様である

序盤は上端に張りついて稼げるが、1000mを超えると上端の猶予は0.8秒台。
プレイヤーは自然に「稼ぐ位置」を下げていく。
**難易度が上がると欲張れる幅が狭まる**＝止め時を自分で決める遊びになる。

### 500mごとに3秒の休憩を入れる

フンも鹿も出ない区間を挟み、地名（一町、二町…）を出す。
エンドレスは緩急が無いと必ず飽きる。ここは削らないこと。

## 6. 理不尽にしない仕組み

エンドレスが壊れる原因はほぼ「抜けられない配置が生成されること」。
配置後に検査するのではなく、**先に通れる道を引いてから、その外側に置く**。

### 安全回廊（corridor）方式

- 幅24px（プレイヤー12px＋余裕12px）の回廊を、参道128pxの中で蛇行させる
- 回廊が1行（16px）で横にずれてよい量は **72 ÷ v(D) px**
  — プレイヤーの横移動72px/sで確実に追いつける範囲。
  3.0タイル/s時で24px、最高速の9.0タイル/s時でも8px（16px行の半分＝10行で80px動かせる）
- フンは回廊の外だけに置く。回廊内には置かない
- 鹿は回廊を**塞いでよい**。ただし塞ぐのは1頭まで、かつ回廊の幅の半分まで

フンは最大密度でも参道の**14%**しか埋めないので、回廊を確保しても見た目の密度は十分出る。
生成のやり直しは発生しない。

### そのほかの保証

- **予兆**: 鹿が画面に入る0.5秒前、上端に印と音。牡鹿はさらに0.8秒のため
- **反応時間の下限**: 安全帯（画面下部）での猶予は距離が伸びても **1.18秒** より下がらない（速度・鹿速度とも上限つき）
- **無敵時間**: 被弾後0.5秒（フン）／1.2秒（鹿）。連鎖事故を防ぐ
- **判定は小さめ**: プレイヤーは足元8×6pxのみ

## 7. スコアと失敗

### ためる
- 距離 ×10
- **高さ倍率** 下端 ×1.0 → 上端 ×2.0（連続変化）
- **連続倍率** フンを踏まず10m進むごとに ×1.1（上限 ×3.0）
- 鹿せんべい ×1.5〜×2.5

### くずれる
- 汚れゲージのみが体力。**10で終了**。フン+1、鹿+3
- 鹿に当たると下へ押し戻される＝高さ倍率も落ちる。二重の罰だが即死ではない
- 結果画面は**汚れた靴の裏を大写し**にして S / A / B / C

## 8. 技術構成

### 実装
- **TypeScript + Canvas 2D + Vite**。160×288のcanvasをCSSで整数倍に拡大、`image-rendering: pixelated`
- 更新は固定タイムステップ1/60秒。描画はrAF。端末差でゲーム性が変わらない
- スプライトは1枚のPNGに詰めてbase64で内蔵。**完全オフライン**
- BGMはWebAudioで矩形波・ノイズを実行時合成（音源ファイル不要、容量ほぼゼロ）。効果音は短いサンプル
- 保存はlocalStorage（★の取得状況、ハイスコア）

### iOSに載せる
- **Capacitor**でラップ。アセット全部ローカル同梱、サーバー参照なし
- オフライン完結＋ハプティクス＋Game Centerを入れておけば「単なるWebサイトの外皮」判定は通常立たない
- 縦画面固定・iPhone先行。レーティング4+（フンはデフォルメ、写実描写なし）
- 実在名は避けて架空の古都に。奈良らしさは残す
